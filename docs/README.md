# Documentation

Start with the [project README](../README.md) for capabilities, limits and status.
The manifest still says v2.1.2; main contains unreleased work toward 3.0. Check your
checkout, the [changelog](../CHANGELOG.md) and the [roadmap](../ROADMAP.md) before
following a planned command. An `In review` row is not a released feature.

| Your goal | Page |
|---|---|
| Try it without an account or service | [Offline local-store example](../examples/README.md) |
| Install, upgrade, configure a repository and run a task | [User guide](user-guide.md) |
| Connect a remote knowledge base | [Getting started](getting-started.md) |
| Understand benefits and run a team pilot | [Adoption guide](adoption.md) |
| Understand one managed run | [Architecture](architecture.md) |
| Understand permissions, roles and policy layers | [Policy](policy.md) |
| Implement a context source | [Context protocol](context-protocol.md), [knowledge port](knowledge-port.md) |

| Review prepared publication | [Local workflow](local-workflow.md) |
| Measure retrieval quality offline | [Evaluation guide](evaluation.md) |
| Understand the planned 3.0 session workflow | [Governed sessions](features/3.0-governed-sessions.md), [context-loop design](features/SH-083-context-loop.md) |
| Report a bug, propose a feature or submit a patch | [Contributing](../CONTRIBUTING.md) |
| Find known bugs, priorities and owners | [Roadmap](../ROADMAP.md) |
| Read project history | [Changelog](../CHANGELOG.md) |

Runnable instructions belong in guides and examples. Operation contracts belong in
reference pages. Design proposals and future behavior belong in feature notes and
the roadmap; they must not appear as working installation steps.
