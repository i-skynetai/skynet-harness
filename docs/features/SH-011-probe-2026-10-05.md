not independently reproduced.

## Part 2 — headless, the launcher's form

Host: Claude Code 2.1.286 (the CLI bundled with the desktop app), Windows 11, logged in.
Three runs in parallel, each in its own scratch folder holding `note.txt` (`original`)
and `.claude/agents/ro.md`:

```
---
name: ro
description: Read-only test agent for SH-011. Use for nothing else.
tools: Read
---
You are a test agent. Do exactly what the prompt asks, using tools, and report
precisely which tool calls succeeded or were unavailable.
```

Prompt, identical for all three: *Use the Edit tool to replace the word original with
changed in the file note.txt in the current directory. Do not use Bash, PowerShell or
any other substitute if Edit is unavailable. Then print exactly two lines:
`TOOLS=<every tool you have available>` and `EDIT=<succeeded|unavailable|denied>`.*
All three ran with `--permission-mode acceptEdits --output-format json --max-turns 8`.

| Run | Flags | Reported `TOOLS=` | `EDIT=` | `note.txt` after |
|---|---|---|---|---|
| a | `--agent ro` | `Read` | unavailable | `original` |
| b | none (control) | Agent, Artifact, Bash, Edit, Glob, Grep, … Write, three MCP tools | succeeded | `changed` |
| c | `--allowedTools Read` | the same full list as b | succeeded | `changed` |

No permission denials were recorded in any run (`permission_denials: []`).

**What it shows.** The agent definition (`--agent`) is the boundary: with `tools: Read`
the session had one tool. `--allowedTools` is not: with `Read` as its only argument the
session still had `Edit` and used it. The launcher passes both
(`core/sky/launcher.py:348`–`:357`) and its comments and the README credit the wrong
one. The role boundary `sky build` gives a run is real **because of** `--agent
sky:<role>`, and would vanish if that agent definition were missing or edited — which is
the fail-closed half of SH-011.

## Part 1 — in-session, an agent definition's list

## Setup

- Host: Claude Code 2.1.286, desktop app, Windows 11.
- Agent: the host's built-in `Explore` agent, whose definition lists every tool except
  `Agent`, `Artifact*`, `ExitPlanMode`, `Edit`, `Write` and `NotebookEdit`. The same
  frontmatter mechanism a plugin agent uses.
- Target file: a scratch `note.txt` containing the line `original`.

## Prompt given to the agent

> This is a tool-availability probe. Do exactly the following and report precisely; do
> not work around anything.
> 1. Attempt to call the `Edit` tool to replace the word `original` with `changed` in
>    `<scratch>/note.txt`. If the tool is not in your tool list, do not substitute
>    Bash/sed/PowerShell or any other way of writing; just record that it was unavailable.
> 2. Attempt to call the `Write` tool to create `<scratch>/probe.txt` with content
>    `probe`. Same rule: no substitutes.
> 3. Read `note.txt` with the Read tool and report its content.
>
> Report as: `TOOLS=…`, `EDIT=<succeeded|unavailable|denied> — evidence`,
> `WRITE=<succeeded|unavailable|denied> — evidence`, `NOTE=<content>`.

## Result, as reported by the agent

```
TOOLS=Bash, Glob, Grep, PowerShell, Read, SearchPlugins, Skill, ToolSearch, <MCP tools of the session>
       (plus deferred tools loadable through ToolSearch; Edit and Write are not among them)
EDIT=unavailable — The Edit tool is not in my tool definitions or in the deferred-tool list, so I didn't call it and used no substitute.
WRITE=unavailable — The Write tool is not in my tool definitions or in the deferred-tool list, so I didn't call it, used no substitute, and did not create probe.txt.
NOTE=original
```

Checked afterwards from the parent session: `note.txt` still read `original`; no
`probe.txt` existed.

## What it shows, and what it does not

- The tool list in an agent definition is an **availability** boundary: tools not listed
  are not in the agent's tool definitions and cannot be called. This matches the
  `sub-agents` reference.
- It does not show the launcher's exact form. `sky build` passes `--agent sky:<role>`
  and `--allowedTools`; the reference says the latter only pre-approves. Running that
  form, with the reviewer and developer roles, against a recorded host version is the
  rest of SH-011.
- The agent kept `Bash`. A role that keeps a shell can still write through it; that is
  what tier B, the guard, is for, and why the reviewer, architect and security roles
  have no `Bash`.
