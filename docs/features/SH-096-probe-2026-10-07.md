# SH-096 — Codex governed implementation boundary probe

**2026-10-07. Maintainer evidence, not installation instructions.** Native
plugin installation is SH-095. Full implementation parity remains SH-096;
this record does not mark it complete or enable a managed developer role.

## What was tested

Codex CLI **0.160.0**, Windows, ChatGPT-authenticated live model calls. Each
probe used a disposable Git repository, an isolated Codex configuration and
private login state removed afterward. No repository was pushed by a probe.
Paths below are relative to that public fixture; no personal paths or tokens
are published here.

The candidate controller is [governed_probe.py](../../hosts/codex/governed_probe.py).
It uses the host's existing app-server approval protocol, not a new model tool.
Its intended boundary is a read-only/no-network base with individual file
approvals checked against the effective Sky policy. It never sends
`acceptForSession`, a write-root grant or a shell escalation approval.
The hardened revision requests `approvalPolicy = untrusted` and maps a small
command vocabulary to granted Sky tools before returning an individual
approval. This value was accepted by the installed app-server; current docs
describe restrictions on selecting it in configuration, so other versions
must be probed rather than assumed compatible.

## Windows diagnostics and the command boundary

Moving the isolated Codex home out of the OS temporary directory allowed
sandboxed commands to start, but the shell could not read fixture files.
Both reading code and importing the generated test failed with access-denied
or import errors. The fixture ACL had SYSTEM, Administrators and OWNER RIGHTS
entries. A normal directory created with `Path.mkdir`, rather than a private
`tempfile.mkdtemp` directory, resolved the read/import failure. No permissions
on a real repository were changed to work around it.

The CLI also rejected the older `readOnly.access` API with:

```text
Invalid request: readOnly.access is no longer supported;
use permissionProfile for restricted reads
```

A named, restricted read profile was accepted as configuration, but the
Windows fallback sandbox then refused to launch a shell because it could not
enforce those filesystem restrictions. The candidate uses a named full-read,
no-write profile, and checks edit destinations separately. This does not
claim restricted filesystem reads are supported by that fallback sandbox.

The fallback also allowed the direct socket diagnostic despite
`networkAccess = false`. Accordingly, the controller now requires untrusted
command callbacks, denies unknown commands and never grants an execution-rule
amendment. A read command and a developer patch passed after hardening; the
socket attempt and reviewer patch were declined. The native network flag is
not advertised as the whole boundary.

**Conclusion:** individual patch approvals are a measured implementation
primitive, and a controller can deny unknown commands before execution.
A complete governed implementation workflow has not passed. Do
not widen to `workspace-write`, approve arbitrary shell commands or use a
failed hook as a substitute for the missing proof.

## Installed native workflow — observed live

The shared launcher now delegates through `codexhost.execute`. It checks
readiness and the current plan admission before execution, and consumes admission
only at the final launch point. Installed procedures and the briefing budget are
checked first. The controller resolves managed policy independently of user
configuration and records both initial retrieval and completed MCP calls.

Arup approved a local dispatch tool on 2026-10-07, changing the earlier design
rule that Sky supplies no tools. Its `implement` and `review` operations accept
a canonical managed repository root and a bounded task; commands, environments
and role overrides are not accepted. It invokes the same launcher, not another
admission implementation. Disconnect/cancellation terminates the launcher tree.

Fresh native installation in an isolated Codex home was followed by these runs:

| Case | Observation |
|---|---|
| `$sky:review` from a read-only parent | Local dispatch completed; the governed child returned file:line findings; run, approval and MCP retrieval records were written |
| `$sky:code` with approval policy `never` | Host refused the mutating MCP call; no launch and no file change |
| `$sky:code`, tool explicitly approved, fresh admitted plan | Runtime consumed admission once; an individual patch created the expected fixture file; `npm test` exited 0 (one test); parent performed no implementation |
| Post-run inspection | Fixture bytes contained `DONE` and newline; admission was used and linked to the runtime run id; actual patch/test completion events matched the report |

The implementation-tool approval was scoped through the documented plugin
per-tool setting in the isolated configuration. No parent shell write permission
was granted. Ordinary users may approve the call interactively instead.

Two packaging fixes were necessary and are included: Codex 0.160.0 does not
expand `${PLUGIN_ROOT}` in legacy MCP arguments, so the server uses a relative
package working directory; Git root discovery closes stdin so Git cannot
consume or wait on the MCP transport. The installed wrapper supplies its own
policy root. Twenty-four focused controller/runtime/transport tests pass, including a
preflight briefing-budget refusal before host execution.
The README, user guide and host setup describe these supported limits.
